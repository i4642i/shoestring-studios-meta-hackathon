# Finding honest pictures

A picture in an explainer video is evidence, not wallpaper. The
viewer should learn something from every image that stays on
screen longer than a glance.

## Source figures first

The client's document may already hold the perfect figure: a
chart, a diagram, a photo with a caption. Open it, read the
caption, check it against the cut's screen idea. A figure that
matches exactly wins over any web search.

## Write short queries

The search backends match plain words, not sentences. Write
each query as 1-2 common nouns naming something a camera could
have seen. No abstract words, no years, no two scenes in one
query. Turn the screen description into such nouns; never copy
the narration words.

Run at most two queries per cut. If a query returns 0 hits,
the second query retries with fewer, more general words. If
neither delivers, the honest answer is "none".

## Judge every hit by its title

Short queries can return off-topic images. Read each hit's
title before picking: it must show what the cut's screen idea
needs. A well-licensed photo of the wrong thing is still a
wrong pick.

## Licenses you may use

cc0, pdm, by, by-sa. Never anything with nd (no-derivatives):
we crop and overlay text, which nd forbids. Record the license
from the search result page, not from memory, and keep the
source URL with the file so the credit line writes itself.

## When to say none

Animation cuts, formula cuts, and abstract transitions need no
photo. Saying "none" early lets Vera plan a clean text card
instead of fighting a photo that does not belong.
