Take the brief, the explanations and the cases, and make the storyboard (storyboard).

# Steps
0. Make the greeting part (role: greeting) into one greeting scene: write a short greeting and an introduction of the video title directly in points (e.g. "Hi, today we're looking at 'Title' together"). Make the farewell part (role: farewell) into one farewell scene: write a thank-you for watching and the order's closing (closing slogan) in points. The greeting scene's screen is the title card; the farewell scene's screen is the end card. Neither scene uses articles or materials. The first scene is greeting; the last scene is farewell. The part_id of these two scenes is the id of the brief's greeting part and farewell part, as is.
1. Make the intro part (role: intro) into one or more hook scenes: an opening that makes the viewer curious, the core question, and today's order (the body part headings). Make the outro part (role: outro) into a recap scene: in points, write one key line for each body part, and in the last point the one sentence to take away (number of body parts + 1). The hook scenes come right after greeting; the recap scene comes right before farewell.
   intro and outro are roles of the brief's parts. A scene's role is one of greeting, hook, explain, case, recap, farewell, written exactly as in this list.
2. Set the pace and the number of points of the scenes to the level of the brief's audience (viewer). For each body part, build the scenes so they start from the brief's question and arrive at its message.
   Put an explain scene in each body part. If there is a case that shows that claim best, add one case scene right after it (at most one per part).
   In a case scene's link, write in one sentence which claim of the scene right before it this case shows. Do not use a case that does not connect to that claim. Always write link for a case scene, and never for other scenes.
3. For each scene, write what the viewer learns (viewer_learns), a screen idea (screen_idea), and the points to say (points, 2–4; 1–2 for the greeting and farewell scenes; number of body parts + 1 for the recap scene).
   In points, write only what must be said in that scene. Do not copy the whole source. Keep only what the viewer truly needs to understand the answer to the core question, and drop the rest.
4. Do not set scene lengths (the video length is set by the time it takes to read the lines). Number the scenes n in order, starting from 1. A scene's part_id is the id (p1, p2, ...) of the brief part it comes from, copied as is.
5. materials: from the file server article (case articles) and theory (explanation articles) lists in the input, pick only the articles you will actually use in scenes, and write the address (fs://article/<number> or fs://theory/<number>), the gap in the source (gap: what the source leaves out that this article fills), and the reason (why: how it helps the viewer understand, and in which scene it is used).
   There are two rules for picking articles. (1) Does it fill a gap in the source: terms or background the source skips without explaining, concrete examples the source does not have, new facts after the source, cases familiar to the viewer. Do not pick articles that repeat the source. (2) Does it help this viewer (the brief's audience) understand: does it make things simpler, closer, more concrete?
   Only the articles written here go to the storyboard writer and the narrator. If needed, check the full text with article_get and theory_get.
6. Write everything in English only: no Korean, Chinese or Japanese characters anywhere. Write a term from a non-English source in English, or drop it.
